That is 2,500 attempts: 2,499 model responses and one timeout. One user prompt per instance, no tools, requested temperature 0, and a 4,096-token completion budget.

Separation: yes. One-dimensional ladder: no.

Strict scores span 9.4% to 87.6%, so these deterministic tasks distinguish the tested systems sharply. But tier aggregates are not monotone because each tier mixes different families. Clankdar reports family/tier profiles; it does not assign a single intelligence level.

Four profiles. No fake IQ.

The profiles partition every v2 cell exactly once by the operation the prompt demands. They expose materially different strengths: the same model can be strong at deterministic execution and weaker at constraint solving. Scores are descriptive pass rates under this run's conditions, not permanent labels.

Policy belongs outside the benchmark.

A relying service can choose relevant profiles, cells, minimum sample sizes, and confidence bounds before evaluation. It should not average away a required weakness, infer identity from a score, or grant tool authority solely because a model passed public puzzles.

Strict means the whole response satisfies the declared answer format and matches. Final block extracts a final line, fenced block, or trailing grid, then compares exactly. It is a formatting diagnostic—not a second leaderboard and not an estimate of “real intelligence.”

Provider errors are shown separately and excluded from valid-response denominators. The nominal 95% Wilson intervals describe observed proportions; pooled tasks are heterogeneous and only ten seeds were sampled per cell. No model is certified to clear a tier.

Four legacy families are excluded uniformly from the screened table: gridpath, sequence, hiddenfn, and gridxf. This removes six cells, or 60 instances per model. Full legacy-suite scores, per-cell counts, exclusions, and original-to-corrected verdict changes remain in the machine-readable report.

What the first clanks taught us.

  • Formatting is part of the contract, not the whole capability story. Some models often explain a solution before giving a correct final answer. We expose that gap without awarding a strict pass.
  • The scorer needs tests, too. The original normalizer erased minus signs and boundaries. A suffix-based diagnostic could match “14” to “4.” Typed comparison and answer-independent extraction now replace both.
  • A hard-looking puzzle can be trivial. The old shortest-path family always had a ten-move route. It was removed from the screened pilot; v2 requires real detours and tests answer diversity.
  • Ambiguity is not difficulty. Legacy sequence and induction prompts left the hypothesis class open. The geometric sequence branch also displayed one fewer term. V2 states finite rule grammars and checks agreement on the query before emitting an induction puzzle.
  • Profiles beat a fake intelligence number. V2 separates the tested systems, but pooled tier scores are not monotone because the family mix changes by tier. Thresholds belong to stable family/tier cells under declared conditions—not to one universal “model level.”

These are small, synthetic, programmatically solvable tasks. Grid transforms are not ARC-AGI, and tool-assisted agents must be evaluated separately from one-response model calls. There is no demonstrated “unsolvable frontier” in this suite.

Earn the measurement.

  1. Freeze the question. Record the suite version, prompt/answer hash, seed set, and exact source revision. Never compare different suites as if they were the same run.
  2. Fix the conditions. Use one response per instance. Record the requested model, endpoint, actual accepted parameters, finish reason, token usage where supplied, and latency. Do not mix tool-assisted and unaided runs.
  3. Keep errors visible. A provider failure is not a wrong answer. A token-limit truncation is a budget outcome, not a silently accepted partial response. Report coverage with pass rates.
  4. Preserve evidence. New runs create exclusive files, never truncate previous results. Report readers reject duplicate instances, incomplete runs, and incompatible coverage.
  5. Use fresh seeds and uncertainty. Compare the same held-out instances across models, inspect every family/tier cell, and predeclare any threshold. Ten successes out of ten still has a Wilson lower bound near 72%, not proof of 90% reliability.

Public seeds make prompts reproducible, not contamination-proof. Published rule sets can be memorized or solved with code. A challenge response never establishes who—or which model—produced it.
