# Contents

- `ladder/` owns versioned deterministic benchmark generators, typed scoring, and the experimental keyed commitment helper. `FAMILIES` is the frozen published v2 pool; `FRONTIER_FAMILIES` (deeper unaided cells) and `AGENT_FAMILIES` (bounded tool-agent cells with server-side `env` tools) are the current published pools. The `*_V0` constants are frozen pools that exactly regenerate the published `frontier-v0`/`agent-v0` archives; `poolForVersion` must keep every published suite version regenerable forever.
- `ladder/algal/` is the ABI/loader boundary for the pinned official Algal expression WASM; `ladder/families/algal.ts` freezes `clankdar-algal-v1`. Never reimplement language operations locally or change the evaluator hash/generator under that version. New checks default to `algal-floor-v1`; prior suites and explicit policies retain their meaning. The Algal suite has no published model calibration yet, and separate Rust admission-checker support is not claimed.
- `bench/` owns bounded adapters (OpenAI-compatible HTTP plus `cli:<program>:<model>` local-CLI adapters that spawn one pinned program per instance with all built-in/MCP tools disabled, so the model gets one unaided text turn), CLI run artifacts, comparison reports, pilot replay, `admission-archive.ts` — packed public evidence directories whose artifact hashes, signed admissions, regenerated instances, typed scores, policies, and summaries are verified before publication; `agent.ts`/`replay.ts` — the TOOL/FINAL protocol loop and deterministic transcript verifier for the agent track — and `attest.ts`/`instance.ts`: the `clankdar-attest-v1` sealed-seed capability attestation reference implementation and its generator oracle (the Rust implementation lives in valhalla `prototypes/clankdar-attest`). `gate.ts`/`store.ts` add `clankdar-gate-v1`: admission sessions (policy → N sealed challenges → one signed admission verdict), the independent admission checker, the durable append-only session ledger, the HTTP gate service, and the drift-probe mode. `tlog.ts` adds `clankdar-tlog-v1`: a derived, hash-chained, verifier-signed transparency log over the gate ledger, with build/check/prove/admit commands (logged-admission checks preserve held-out `unreplayed` counts and accept a disclosed pool), a local signed-head witness registry with equivocation detection, `compare` — a cryptographic fork check between two published logs — and `witness-serve`, a bounded provider-neutral HTTP intake keyed by each head's embedded verifier key, with optional interval polling of configured providers' `/tlog/head` endpoints. `badge.ts` adds `clankdar-badge-v1`: subject-signed portable badges that aggregate subject-bound admissions across issuers, with pack/check commands, optional tlog inclusion proofs, and up to 64 disclosed holdout pools indexed by `poolKey`; undisclosed scores remain counted in `unreplayed`. `holdout.ts`/`canon.ts` add `clankdar-holdout-v1`: issuer-private pools that re-parameterize published generators with secret labels (`h:family:tN` policy cells, `heldout.poolKey` challenge markers, three-way receipt checking). `hosted.ts` adds the hosted issuer surface: one HTTP service composing the gate handler and the derived tlog — every gate route plus `GET /tlog`, `GET /tlog/head` (the signed head a witness pins), and `GET /tlog/proof/:sessionId`, with `serve` and `head` commands; `keys.ts` adds optional issuer-side client keys — hashed bearer tokens with per-key mint quotas in an append-only store, wired into the mint route via `serve --auth-keys` and the `keys` CLI commands.
- `docs/` owns protocol specifications. `docs/clankdar-attest-v1.md` is the `clankdar-attest-v1`/`clankdar-gate-v1`/`clankdar-tlog-v1`/`clankdar-badge-v1`/`clankdar-holdout-v1` wire format plus the `clankdar-admission-archive-v1` publication envelope, checking procedure, ledger requirements, and threat model — the contract the Rust implementation tracks.
- `cloudflare/` owns the standalone check API and the retained actor reference application. `docs/clankdar-checks-v1.md` is the primary integration contract: issue a sealed ticket, submit answers once, retain one canonical `clankdar-gate-v1` admission in R2 at `checks/<id>.json`; a conditional create freezes the authoritative result and D1 holds only the standalone issuance quota. Actor registration and campaigns are not prerequisites. Preserve the distinction between receipt validity and pinned-issuer/application acceptance. The retained actor API uses a Worker front door, one SQLite Durable Object per `clank1_…` actor for serialized nonce/event state, D1 as the rebuildable public directory/anchor projection, and R2 for immutable content-addressed evidence. `docs/clankdar-hosted-v1.md` is its claim/threat/cost contract. Registration is bearer-gated in staging; actor mutations are Ed25519 request-signed and one-use-nonce protected. Heartbeats prove only key continuity/activity, never autonomy or capability. Campaigns precommit cadence and denominators, preserve misses, issue one-use puzzle sessions, require actor subject proofs, encrypt live tickets, publish compatible gate admissions to R2, and reveal schedule seeds; profiles keep availability/capability separate and explicitly deny model identity or uniqueness.
- `demo/` owns the credential-free local first check (`bun run try`): shared issue/submit primitives, an ephemeral signer, public-prompt scripted control or explicit caller solver, independently verified canonical receipt, and unique public-evidence outputs. Never imply that a local demo key is a trusted hosted issuer, execute a model implicitly, or expose seeds/expected answers to the solver callback.
- `site/` owns the static marketing and documentation pages for clankdar.com. The homepage practice fixtures execute in Algal at build time; a small same-origin script uses the shared exact scorer. They are public practice, never issued checks or signed receipts. Keep the browser practice offline, with a usable no-script solution. The downloadable JavaScript HTTP helper is copied from `cloudflare/examples/check.mjs` during the build, not maintained separately.
- `site/benchmark/` holds the published calibration archives: `pilot-v0` (intentional legacy data), `v2-calibration-0`, `frontier-v0`, `agent-v0`, and `admissions-opus5-2026-09-19` (four signed gate sessions verified during the site build); private runtime results stay in ignored `results/`.
- `site/build.ts` is the bundling entry; `site/dist/` is generated output.
- `vercel.json` sets the static build, output directory, and content security headers.

# Guidelines

- Use Bun 1.3.14. Run `bun run check` before handoff: strict Node and Workers typechecks, Bun tests, Cloudflare runtime tests, pilot replay, and static build. Use `bun run check:site` for focused site iteration. Run `wrangler deploy --dry-run --config cloudflare/wrangler.jsonc` for hosted changes; never deploy while the D1 id is the all-zero placeholder or without `ISSUER_JWK`, `SESSION_WRAP_KEY`, and `REGISTRATION_TOKEN` in Cloudflare Secrets.
- Run `bun run check:browser --channel chrome` on machines with Chrome, or install Playwright Chromium and omit the channel flag. The check owns an ephemeral loopback server; retain its ignored screenshots.
- Deliver post-bootstrap changes through a current-head pull request with passing checks. Keep deployment identity and legacy redirects intact.
- Keep pages static HTML with no client framework, no forms, and no third-party
  requests; the deployed CSP forbids all of them.
- Load presentation only from the pinned `@hraness/design-kit` release and the
  pinned `@hraness/site-footer` release; never vendor or fork their files.
- Every page contains exactly one `<!-- hraness-site-footer -->` marker; the
  build fails otherwise. The footer is configured with
  `mailingList: { kind: "none" }` and no support profile.
- Keep the shared appearance menu as the final header action.
- Keep every public claim true and scoped to what shipped. This is an internal claims rule; it is not wording for public pages, which follow `STYLE.md` and its Clankdar glossary under “Repository additions”. The claims ledger: the benchmark is implemented; `clankdar-attest-v1` and `clankdar-gate-v1` are implemented as a TypeScript reference plus a Rust attest prototype in valhalla — a receipt attests one signed response inside one window, and an admission attests K passing responses under one policy in one window; neither is identity, liveness, or authority. `clankdar-tlog-v1` is implemented as a derived signed log over the gate ledger — TypeScript builds and serves it, while Rust independently checks logs and logged admissions — and it makes issued events enumerable and accountable but binds history only under the issuer's own key; the local head-witness registry detects same-count and same-tip equivocation from heads and proves any fork between two published logs by chain comparison; a pinned head's holder verifies later growth with a linear suffix consistency proof (`prove --from-count`/`check-proof` — linear in growth, not Merkle-logarithmic, since the log is a hash chain by design); a bounded provider-neutral HTTP intake accepts self-describing signed heads under many verifier keys without a provider registry, and can poll operator-configured providers' `/tlog/head` endpoints on an interval. Provider discovery, gossip, witnessed co-signing, external anchoring, and witness-side provider quotas are not implemented — a private fork stays invisible until both views reach one witness. `clankdar-badge-v1` is implemented in TypeScript with independent Rust checking as subject-signed portable badges over subject-bound admissions — a badge proves the subject key accumulated the admissions, never that the holder solved or earned them, and it is not an identity; held-out admissions without a disclosed matching pool remain valid issuer claims but MUST surface in `unreplayed`, while pool sets may mix issuers and are keyed only by committed `poolKey`. `serve` offers optional ledger-derived rate limits (global open/mint bounds plus per-subject pacing) — hard bounds are global since subject claims can be rotated. `clankdar-holdout-v1` is implemented in TypeScript and Rust as issuer-private label-parameterized pools — a held-out cell is the same puzzle family under a secret stream, so receipts without the pool verify the envelope but not the score (`replayable:false`), and publishing the pool restores verifiability; a general family solver still solves held-out cells. The hosted issuer surface is implemented as a reference composition of the gate HTTP handler and the derived tlog — it publishes signed evidence (log, head, inclusion proofs) but does not stop self-minting, fork detection still needs published-head comparison at a common witness, and a production deployment (TLS termination, witnessed co-signing) remains unimplemented — optional bearer-key client authentication with per-key mint quotas is implemented for the hosted write path, but it is authorization for ledger writes, never identity. Valhalla's Rust rooms mode dogfoods gate decisions pinned to a room floor and verifier key, but is not wired into join authorization and refuses unreplayed held-out scores. Hashcash and witness are Rust prototypes in valhalla. Tier numbers are parameter settings, not certified model classes.
- Preserve the distinction between the legacy pilot and the corrected v2 suite. Never silently compare changed prompts, seed semantics, or scorer versions. Publish model results only with recorded evidence, counts, exclusions, and provenance limits.
- Keep the three tracks strictly separate: v2 and frontier are unaided single-response suites; the agent suite measures bounded tool use with recorded transcripts and must never share a leaderboard with unaided results. Agent instances carry `env` tools that are deterministic closures over generated data — never expose shell, network, secrets, or ambient filesystem.
- Frontier and agent suite generators mix a per-(family,tier) label into the seed so same-seed answers decorrelate across families; the public seed recorded in results stays the caller's seed.
- Never send answers or seeds to model adapters, log provider error bodies or credentials, or overwrite existing run files. Model CLI calls must remain opt-in and request-bounded.
- Keep text case, numeric signs, token boundaries, grid dimensions, and binary leading zeroes meaningful. Final-block extraction must not use the expected answer to select a candidate.
- The 32-bit benchmark RNG is not an admission generator. Keyed answer commitments require a verifier-secret key and do not implement signatures, subject/scope binding, expiry, or durable replay protection.
